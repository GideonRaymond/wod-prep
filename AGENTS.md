## Project conventions

- `src/app/` holds routes only. Page UI lives in `src/components/<page>/` and the page file just renders it.
- Generic, reusable UI goes in `src/components/shared/`. Build new UI from these (Button, ButtonLink, TextArea, TextInput, Select, Card, Badge, CategoryBadge, Alert, Dialog, FieldError, CharacterCount, IntensityGauge, MovementDetails) instead of styling raw elements. `WodBoard` (the chalkboard, drawn in `BoardFrame`, which the paste box sits in too) and `BoardLayout` (board beside the page) are shared by every step; pages render through `FlowPage` (centered stepper, then the board on the left), so the board starts in the same place on each.
- One folder per component: `Name/Name.tsx`, `Name/Name.test.tsx`, `Name/index.ts`. Import through the folder (`@/components/shared/Button`).
- The flow is three routes, shown by `Stepper` with the steps in `src/constants/flow.ts`: `/` (paste; parsing writes the board up as it goes), `/review` (edit beside the board; `src/components/review/`), `/workout` (loading screen, then the class).
- App-wide state in `src/providers/` (e.g. `WodProvider`, the current workout shared by the review and workout pages). It reads from a store in `src/stores/` (`wodStore`) via `useSyncExternalStore`; every change (and the text the workout was parsed from) is written through to sessionStorage so a refresh restores it. Don't read `sessionStorage` during render elsewhere — it isn't available on the server.
- Hooks in `src/hooks/`, client API calls in `src/services/`, server-only code in `src/server/`, Zod schemas in `src/schemas/`, constants in `src/constants/`, hand-written content in `src/data/`, pure helpers in `src/utils/`.
- Claude calls use the shared client in `src/server/anthropic.ts`. Routes map errors with `claudeErrorResponse` (`src/server/apiErrors.ts`). Caching goes through `createCache` (`src/server/cache.ts`): Upstash Redis in production (`getRedis` in `src/server/redis.ts`), JSON files in `.cache/` in development. Videos: hand-picked ones in `src/data/movementVideos.ts`, otherwise YouTube search in `src/server/movementVideos.ts` (key `YOUTUBE_API_KEY`) ranked by Claude in `src/server/rankVideos.ts`; cached per movement for 30 days. Articles: Claude with web search/fetch in `src/server/articles.ts`, per workout part; only URLs seen in its search results are kept; cached for 30 days. Warm-up and skills: one Claude call per workout in `src/server/classPrep.ts`; the time budget, fitting and stage order (skills right before the part that uses them) live in `src/utils/classPlan.ts`. Whiteboard: the outline call writes each part's `board` lines; the board stays as read while editing, and parts edited since (`boardOutdated` in `src/utils/partKey.ts`) are redrawn on the workout page by `useBoardRedraw` through `/api/board` (`src/server/redrawBoard.ts`, `FAST_MODEL`). The board's blocks come from `src/utils/boardItems.ts`: the parts as written (`partsBoard`), or the whole class in order with the planned warm-up, skills and stretches as one line each (`classBoard`). On the class page the board is the table of contents (`nav` on `WodBoard`): blocks jump to their stage, the one on screen is outlined, and on phones it folds into a sticky bar instead of a Jump to button. Cool-down stretches: hand-picked library in `src/data/stretches.ts`, chosen per workout by `src/utils/suggestStretches.ts` (no API call).
- Parsing is two steps (`src/server/parseWod.ts`): a quick outline with `FAST_MODEL`, then each part's details in parallel, streamed to the client as NDJSON `ParseEvent`s (`src/types/parse.ts`, read by `src/services/wodApi.ts`). Test helpers for the stream are in `src/test/parseStream.ts`.
- The workout page's loading screen (`src/components/workout/LoadingScreen`) is driven by `classChecklist` and the hand-over by `useHandOver`. The handwriting fonts load only in `WodBoard/fonts.ts`; tests mock `next/font/google` in `src/test/setup.ts`.
- Routes call `mockLoad(kind)` (`src/server/mockLoad.ts`) before returning a cached or hand-picked result, so `MOCK_LOAD=true` shows the loading screens with cached data. Do the same in new routes.
- Routes call `rateLimit(request, kind)` (`src/server/rateLimit.ts`) after a cache miss, right before calling Claude or YouTube, and return its 429 when it gives one; cached and hand-picked results don't count. Every API route exports `maxDuration` (at most 60, Netlify's ceiling). Do the same in new routes.
- Middleware is `src/proxy.ts` (Next.js 16 name), one file only: the shared-password gate (`SITE_PASSWORD`). It uses only Web APIs (no Node.js modules), so it runs on any host.
- Every change comes with tests next to the code it covers.
